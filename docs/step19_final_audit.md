## 보존 및 보안 확인 — CONFIRMED

- 운영 DB는 tracks 14행, spotify_chart 23행, youtube_stats 97행으로 총 134행.
  전체 열을 PK 순으로 직렬화한 전후 SHA-256과 운영 스키마 메타데이터가 동일했다.
- 원본 CSV·facts·승인/정정·기사/검수·실제 .env·SQL 등 보호 파일 38개와
  당시 추적 파일 전체 149개의 바이트 해시가 동일했다.
- 전역 Python 패키지 35개의 이름·버전 목록이 동일했다. 전역 설치·업그레이드 없음.
- 운영 DB 쓰기는 수행하지 않았다. DDL·시험 쓰기는 각 테스트가 새로 만든 고유 이름의
  `mbc_kpop_step19_test_*` DB에서만 실행했으며 각 테스트가 만든 DB만 정리했다.
- 실제 .env·가상환경·캐시·검증 산출물 제외 규칙 확인. 캐시 4개는 추적만 해제됐다.
- 추적 파일의 대표 비밀키 패턴 검사 일치 0, 실제 .env 추적 없음,
  로컬 전체 ref의 .env 경로 이력 0건. 전체 이력·모든 비밀 형식의 무유출 인증은 아니다.
- 점검 전후 작업 폴더가 깨끗했고, 점검 자체에서는 새 Commit/Push를 하지 않았다.

위 파일·행·패키지 개수는 **검증 기준 Commit의 점검 당시 수치**다.
이 보고서와 인수인계 문서 추가 이후의 추적 파일 개수와 구분한다.
개인 PC 경로·원시 DB/환경 덤프·상세 실행 로그·검증용 임시 스크립트는 이 문서에 포함하지 않는다.

## 남은 사항과 미검증 범위

**CONFIRMED — 기존 구조의 한계 및 후속 정리**

- Current Analysis와 승인 토큰은 프로세스 메모리에 있으며 재시작·다중 worker 공유가 없다.
- tracks의 artist+track 고유키는 없다. 현재 중복은 0이지만 여러 작성자의 중복 방지는 별도 정책이 필요하다.
- Chart.js CDN 버전이 고정되지 않았고 구형 youtube_test.py 등에 timeout 없는 호출이 남아 있다.
- 과거 패치·HTML 백업은 보존했다. STEP11/16의 설치 시점 UI/payload 바이트 검증은 현행 합격 기준과 다르며 이번에는 재실행하지 않았다.

**RESEARCH / HYPOTHESIS — 현재 발생한 결함으로 단정하지 않음**

- 서로 다른 토큰의 동시 최초 승인 경쟁은 격리 재현이 필요하다.
- DB commit과 승인 JSON 기록은 하나의 원자적 트랜잭션이 아니다.
  중간 실패·디스크 오류·불명확한 commit 결과의 장애 주입과 수동 대조/복구 절차가 필요하다.
- 손상 승인 이력의 안전 차단은 시험했지만 화면 전체로의 오류 전파·복구는 미검증이다.
- 새 DB song_id와 승인 JSON의 곡 정체성 연결, 실제 백업 복원은 별도 확인 대상이다.
