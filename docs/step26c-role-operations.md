# STEP 26C 관리자·역할 운영 절차

## 현재 확인 결과

2026-10-20 로컬 설정의 인증 저장소를 읽기 전용으로 확인했습니다. ADMIN 0개, READER 2개입니다.
운영 계정의 비밀번호·역할·세션·감사 이력은 변경하지 않았습니다.
아래 지정 절차는 아직 실행하지 않았으며, 사용자 승인 후 운영자가 수행해야 합니다.

## 역할별 이용 범위

| 역할 | 개인 분석 | AI News·기사 작성 | YouTube 영상 후보·검수 | 기사 검수·승인 | 역할 변경 |
|---|---|---|---|---|---|
| READER | 가능 | 불가, 승인 기사 조회 가능 | 불가 | 불가 | 불가 |
| JOURNALIST | 가능 | 가능 | 불가 | 불가 | 불가 |
| EDITOR | 가능 | 가능 | 가능 | 가능, 본인 작성 기사 제외 | 불가 |
| ADMIN | 가능 | 가능 | 가능 | 가능, 본인 작성 기사 제외 | 가능 |

개인 분석은 기존 데이터를 선택할 뿐 원본 데이터를 수집·변경하지 않습니다.
기존 STAFF 원본 저장 기능의 권한과 별도 확인 절차는 유지됩니다.
유료 AI 생성은 별도 확인이 필요하며, 후보 검색은 YouTube API 할당량을 사용합니다.

## 1. 관리자 존재 여부 확인

VS Code 터미널에서 실제 서버와 같은 가상환경 및 프로젝트 폴더를 사용합니다.
`KPOP_AUTH_DB`를 별도로 지정한 서버라면 CLI에도 동일한 경로를 명시해야 합니다.
CLI는 `.env`를 자동으로 읽지 않으므로, `.env`에만 설정한 경우 환경변수를 먼저 설정합니다.
설정이 없으면 프로젝트의 `data/private/editorial.sqlite3`를 사용합니다.

```powershell
python -m security.admin status
```

이 명령은 SQLite를 읽기 전용으로 열며 ADMIN 개수만 출력합니다.
저장소가 없다고 표시되면 경로를 먼저 확인합니다. 기존 운영 저장소에 `init`을 실행하지 마세요.

## 2. ADMIN이 없는 경우 — 최초 관리자 지정

1. 관리자로 지정할 기존 가입 계정을 사용자와 확인하고 **명시적인 승인**을 받습니다.
2. 승인받은 계정명과 실제 인증 저장소 경로를 다시 확인합니다.
3. 해당 계정의 소유자가 터미널에 비밀번호를 직접 입력합니다. 비밀번호를 채팅·명령 인자·문서에 남기지 않습니다.

```powershell
python -m security.admin bootstrap --username 승인받은_기존_아이디
```

기존 bootstrap은 ADMIN이 이미 있으면 중단하고, 등록 계정의 현재 비밀번호를 확인한 뒤 최초 ADMIN을 지정합니다.
비밀번호를 재설정하지 않습니다. 기존 세션을 해제하고 `BOOTSTRAP_ADMIN` 감사 이력을 추가합니다.
지정 후 Account에서 다시 로그인하고 Editorial의 ‘사용자 역할 관리’가 표시되는지 확인합니다.

## 3. ADMIN이 이미 있는 경우 — 관리자 화면 이용

1. 기존 ADMIN 계정으로 로그인합니다.
2. Editorial → 사용자 역할 관리에서 대상 계정을 확인합니다.
3. 필요한 최소 역할을 선택합니다. ADMIN 추가 지정은 반드시 사용자 승인을 먼저 받습니다.
4. ‘역할 변경’을 누르고 대상 아이디·변경 전후 역할을 확인한 뒤 승인합니다.
5. 대상 사용자는 다시 로그인합니다. 기존 세션은 서버에서 해제됩니다.

역할은 서버의 ADMIN 전용 API로만 변경하며 `ROLE_CHANGED` 감사 이력을 유지합니다.
READER의 자기 승격, 직접 SQL 수정, 임의 비밀번호 변경은 사용하지 않습니다.
마지막 ADMIN을 해제하는 요청은 기존 서버 정책에 따라 차단됩니다.

## 4. 재로그인 후 검증

- JOURNALIST: 개인 분석 및 기사 초안 저장·검수 요청 가능, 영상 후보 조회·기사 승인 불가.
- EDITOR: 영상 후보 조회 가능, 다른 작성자의 기사 검수·승인 가능.
- ADMIN: 위 기능과 사용자 역할 관리 가능.
- READER: 개인 분석과 승인 기사 조회 가능, 작성·검수·역할 변경 불가.

기사 작성자와 승인 편집자는 서로 다른 계정을 사용해야 합니다.
화면에서 버튼을 숨기거나 비활성화하는 것은 안내용이며, 최종 권한 검증은 서버가 수행합니다.
직접 API를 호출해도 역할 제한을 우회할 수 없습니다.

## 오류 구분

- 앱 401: 세션이 만료되었거나 로그인이 필요합니다.
- 앱 403: 필요한 역할 또는 로컬 요청 조건을 충족하지 못했습니다.
- YouTube 429: API 할당량·요청 한도 초과입니다.
- YouTube 502: API 접근 설정·키 권한·연결·응답 문제입니다.
- YouTube 503: API 키 설정이 필요합니다.
- 후보 404: 검토 가능한 영상 후보가 없습니다.

오류 해결을 위해 사용자 역할을 무조건 올리거나 검수·승인 정책을 우회하지 않습니다.
