## 문자열 비교와 UNIQUE

각 셀은 `비교 결과 / 두 번째 값 INSERT 허용 여부`다.
MySQL과 PostgreSQL 실제 엔진의 새 합성 DB에서 시험했다.
MySQL은 `utf8mb4_0900_ai_ci`, PostgreSQL은 새 DB의 기본 TEXT 비교,
후보는 `provider=icu, locale=und-u-ks-level1, deterministic=false`를 사용했다.

| 합성 값 | MySQL | PostgreSQL 기본 | PostgreSQL ICU 후보 |
|---|---|---|---|
| A / a | 같음 / 거부 | 다름 / 허용 | 같음 / 거부 |
| e / é | 같음 / 거부 | 다름 / 허용 | 같음 / 거부 |
| é / e + 결합 악센트 | 같음 / 거부 | 다름 / 허용 | 같음 / 거부 |
| x / x + 후행 공백 | 다름 / 허용 | 다름 / 허용 | 다름 / 허용 |
| 가 / 나 | 다름 / 허용 | 다름 / 허용 | 다름 / 허용 |
| same / same | 같음 / 거부 | 같음 / 거부 | 같음 / 거부 |

시험은 PASS다. 다만 기본 PostgreSQL의 문자열 비교가 MySQL과 같다는 뜻은 아니다.
ICU 후보가 이번 6개 사례에 일치했지만 전체 Unicode와 모든 언어의 동등성을 입증하지 않는다.
기존 앱 스키마·컬럼·인덱스는 변경하지 않았다.
운영 이전 전 컬럼별 비교 정책 결정, 확장 사례 및 실제 이전 자료의 중복 충돌 검증이 필요하다.

## 최소 권한 앱 역할

`kpop_step27a3_app_20261020` 역할을 새 PostgreSQL 합성 DB에만 명시적으로 권한 부여했다.
실제 별도 로그인으로 필수 CRUD와 앱의 가입·로그인·개인 선택·기사 제출·승인을 확인했다.
슈퍼유저, DB 생성, 역할 생성, 복제, RLS 우회 권한을 주지 않았다.
테이블 소유자는 관리자이며 앱 역할은 소유자가 아니다.

다음 14개 제한이 모두 SQLSTATE 42501로 거부되었다:
테이블 생성, 임시 테이블 생성, ALTER, DROP, TRUNCATE,
이력 UPDATE/DELETE, 트리거 비활성화, 트리거 함수 교체,
postgres 역할 전환, postgres 역할 부여, DB 생성,
시스템 비밀번호 카탈로그 조회, 미허용 시험 테이블 조회.

이력 테이블에는 SELECT/INSERT만, 일반 앱 테이블에는 실제 경로에 필요한 DML만 부여했다.
시퀀스에는 USAGE/SELECT만 부여했다. 다른 DB의 PUBLIC 권한은 변경하지 않았다.
이 시험은 서버 측 서비스 계정의 권한 경계이며, 사용자별 접근 제한은 기존 앱 인증 로직이 담당한다.
DB 계정만으로 사용자별 행 격리/RLS를 검증한 것은 아니다.
시험 종료 시 역할을 NOLOGIN으로 전환했다. 생성된 비밀번호는 저장하지 않았다.
